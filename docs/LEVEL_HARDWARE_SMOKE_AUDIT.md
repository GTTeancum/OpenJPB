## Gate Definitions

- `loaded`: the canonical runtime level ID was reported; FBX is optional for JPX-only levels.
- `rendered`: hardware mode requires final-frame world-only GPU linear-depth coverage before actors/HUD; headless mode requires scene pixels. Both require scene triangles and a final PPM capture.
- `textured`: hardware mode successfully resolved every FBX-declared world material texture; headless mode marks this not applicable.
- `framed`: the actual player model contributed pixels in at least one sampled frame, and hardware mode also requires a nonzero final-frame player contribution.
- `camera`: the recovered camera collision result is positive.
- `keyboard`: the spawn input owner is keyboard and virtual key state was recorded.
- `control`: ordinary levels require an isolated virtual `W` probe with at least 30 directional frames, at least 30 locomotion frames or a real vehicle attachment, and more than 16 world units of horizontal travel. Corus1 follows its retail 0xc00 start heading with 170 virtual D frames, then releases input after the JPX collision handoff to dolly 53. Mini2 instead requires its PDB-owned alternating K/Space Kaadu cadence to grow a race bar to at least 128 pixels and move the mounted rider. Each attempted protocol has its own console log and frame capture.
- `complete`: the requested frame budget completed without timeout.
- `presenter`: hardware mode created the D3D11 hardware presenter and presented every requested frame; headless mode marks this not applicable.
- `performance`: hardware mode sustained at least 45 measured frames per second over the capture; headless mode marks this not applicable.
- `crashFree`: no fatal, assertion, sanitizer, or unhandled-exception marker appeared.
